# iOS APNs 토큰 준비 및 복구 — #264

## 기준과 현상

- 기준: PR #240의 `214fee862b5eaccf7b03404d47cc6c847ae64cc2`
- 작업 브랜치: `fix/ios-apns-token-recovery-264`
- 2026-11-15~16 QA에서 로그인은 성공하지만 원격 등록 플래그가 true이고 Firebase APNs 토큰은 없는 상태, FCM 발급 오류 505를 확인했다.
- 원격 등록 플래그는 실제 APNs 토큰 준비를 대신하지 못한다. SDK는 이미 원격 등록된 기기에서는 등록 호출을 바로 완료할 수 있으며, FCM 발급은 별도로 Firebase에 연결된 APNs 토큰을 요구한다.
- 최초 APNs 전달 누락의 근본 원인과 운영 빌드의 동일 증상은 확정하지 않는다.

## 반영한 흐름

1. iOS에서 등록 상태와 Firebase APNs 토큰을 확인한다. 미등록 기기는 등록부터 진행하며, APNs 조회의 `messaging/unregistered`도 준비되지 않은 상태로 처리한다. 다른 조회 오류는 그대로 전달한다.
2. 등록 플래그가 true여도 APNs가 없으면 원격 등록을 해제하고 다시 등록한다.
3. 재등록 후에도 Firebase APNs가 없으면 Expo 네이티브 경로에서 실제 iOS 토큰을 얻는다. iOS 타입·비어 있지 않은 짝수 길이의 16진수 문자열인지 확인하고 `setAPNSToken`으로 연결한다. APNs 길이를 고정하지 않는다.
4. Firebase APNs 준비를 다시 확인한 뒤 자동 초기화를 켜고 FCM 토큰을 발급한다. 서버에는 기존대로 FCM 토큰만 전송한다.
5. 각 비동기 단계 이후 현재 회원 세션을 재확인한다. 대기 중 세션 종료·늦은 응답은 이후 연결·FCM 발급·서버 등록으로 이어지지 않는다.

Firebase 수동 등록과 Expo 토큰 조회는 각각 10초로 제한한다. 이는 전체 로그인·푸시 등록에 대한 10초 제한이 아니다. 타임아웃은 운영체제의 등록 요청 자체를 취소하지 않지만 늦은 Promise 완료가 이 함수의 다음 발급 단계로 진행하지 않도록 한다. 자동 재시도 정책·기존 기기 정리 정책은 별도로 유지한다.
